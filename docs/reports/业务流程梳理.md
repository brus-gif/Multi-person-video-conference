## 一、项目本质（一句话模型）

MeetingGrid 是一个**"单人即可演示、一键升级为真实多人"的视频会议应用原型**：
- 程序始终呈现"一间会议"：默认以**主持人**身份开本地会议，房里除自己外是**演示假人**；
- 一键连自研信令服务器后，假人被**真实远端成员**替换，进入真实多人会议；
- 摄像头/麦克风/屏幕以 WebSocket 帧中继在成员间流转（演示级，非 WebRTC）；
- **本地演示 ↔ 联网会议是同一主窗口的两种会话形态，可往返切换**，媒体设备与多数设置共用。

## 二、角色与实体模型

| 实体 | 说明 | 落点 |
|---|---|---|
| 自己（Self） | 本地用户；**UI 恒把"自己"放 m_members[0]（索引0宫格）**；本地演示下身份=主持人；联网下以服务器 isHost 为准 | MainWindow.h:237；populateFromNetwork 自 prepend |
| 演示假人 | 仅本地演示存在：名字/颜色取自池、麦/像随机、无 id、画面=模拟动画 | nextMember() MainWindow.cpp:558-569 |
| 远端真实成员 | 联网下由服务器下发（id/name/mic/cam/sharing/isHost） | SignalingClient::Member |
| 主持人 Host | =房间创建者；主持人离开→房间关闭广播 room_closed | SignalingServer::closeRoom |
| 房间 | 9 位数字会议号，上限 49 | server |
| 媒体流 | 摄像头 JPEG≤640 ~10fps；麦克风 PCM 44.1k/mono/Int16；屏幕 JPEG≤1280 ~4fps | MainWindow 推/收流 |

## 三、模式划分（用户确认口径）

### 维度一：会话形态（主模式，互斥切换）
| | **A. 本地演示模式（默认）** | **B. 联网会议模式** |
|---|---|---|
| 进入 | 启动即进入（默认 4 人 2×2） | "联网会议"→ 连服务器 → 建会/入会 |
| 房间 | 本机自演 | 服务器托管（创建者=主持人） |
| 成员 | 自己 + 假人（1~49 可调） | 服务器下发，进出实时增减 |
| 麦/像 | 真实采集或模拟回退；本地呈现/说话检测 | 真实采集并推流同房成员 |
| 屏幕共享 | **本地共享不可用（行为变更已批准）**：共享按钮**置灰禁用（不可按下）**并提示"仅联网可用" | 抓屏 4fps 推流 + sharing 广播；**开启共享默认直接关闭摄像头**（v1.1）且**共享期间摄像头按钮置灰禁用**（v1.3）|
| 聊天 | 本地回显 | 服务器广播（含发送者回显） |
| 成员管理 UI | 右侧滑块/预设/增删 | 隐藏，由服务器事件驱动 |
| 视图/计时/设置/开关 | 两形态均可用 | 同左 |

### 维度二：视图形态（模式内正交，两形态均可用）
- 宫格视图 Gallery：全员等大铺满（1→1×1 …49→7×7）。
- 演讲者视图 Speaker：主讲大画面（约 78% 高）+ 其余缩略条。

### 维度三：功能开关（非模式）
麦/像/共享/聊天面板等开关型状态；业务后果随会话形态而异。

> 用户确认：**不存在其它会话模式**；假人=本地演示的合法产品形态（不只开发占位）；视图与开关是模式内正交维度。

## 四、会话形态 A：本地演示模式业务流程（已确认，含修订点）

```
启动(--members=N) → "本地会议"开始（计时即走）
  自己[0]：摄像头(授权→真实/否则模拟回退)；麦克风真实采集 + 说话检测
  假人：模拟动画画面，2×2 起步
① 增减成员：滑块/预设/按钮 → 宫格重排（1~49）
② 我的麦/像开关：真实启停；宫格图标与右侧列表联动；关像→剪影+清残留帧
③ 我说话：RMS+滞回 → 我的宫格绿框（列表同高亮）
④ 点击宫格：本地演示=保留"模拟该成员说话"（绿框）+ 演讲者视图下切主讲
⑤ 宫格/演讲者视图切换
⑥ 聊天：本地回显
⑦ 共享：共享按钮**置灰禁用、不可按下**，提示"仅联网可用"；
    原有"离会/断开自动停止共享屏幕"等逻辑保留不变（行为变更见《项目修改计划.md》，B1）
⑧ 设置：设备/填充模式/模拟帧率
⑨ 结束会议：确认后退出程序
```

## 五、会话形态 B：联网会议模式业务流程（已确认，含修订点）

### B.0 服务端
建会/入会/退会、成员列表、状态广播、聊天中继、媒体帧透传、心跳清理(120s)。
> **v1.4 注**：服务端对每名新成员初始化为 `micOn=true, camOn=true`（join/create 不携带本端状态），即**入会时自己的 cam/mic 展示状态以服务器快照为准**。

### B.1 建会/入会
```
点"联网会议"(离线) → 对话框{服务端地址|房间号(空=新建)|名字}
  ├─ 新建：create_room → room_created + joined(自己)
  └─ 加入：join_room → joined(全量)；错误(error)→弹窗停留本地
成功 → 联网形态：演示控件隐藏、共享按钮恢复可用、按钮变"离开会议"、顶栏真实会议号
状态来源（v1.4 确认）：入会后自我 cam/mic 展示 = 服务器快照（默认开）；
  本地推流连接 = 由本地"摄像头按钮"状态决定：默认开 → 入会/源重建后即连接就绪（见 B.4 规则 0）
〔修订 B4〕若本地真实设备状态与服务器登记不一致（如入会前已手动关摄像），
          属状态校准缺陷，另行处理（本方案不做）
```

### B.2 会议进行中
| 事件 | 服务器 | 呈现 |
|---|---|---|
| 有人加入/离开 | member_joined/left；房主离开→room_closed | 宫格增减；房主离开弹"会议已结束" |
| 我开关麦 | set_state → member_updated | 本地即时；他人图标更新 |
| 我开关摄像头 | set_state → member_updated | 本地即时（含推流启停）；他人图标/画面更新；**联网共享中该按钮禁用（v1.3）** |
| 我开关共享 | set_share → member_updated(sharing)；本地抓屏推流；**开启共享默认同时关摄像头(cam=false)** | 他人宫格显示共享画面+“共享中”角标；**共享期间我端摄像头按钮置灰禁用（v1.3）** |
| 媒体收发 | 二进制透传 | 真实画面替换模拟占位；音频播放 |
| 聊天 | chat 广播 | 全员追加（含自己回显） |

### B.3 离开/关房/掉线（〔修订 v1.5〕离会细节）
- 我(主持)结束 → leave_room → 服务端关房 → 剩余成员收 room_closed → 各自回本地演示；
- 我(成员)结束 → member_left → 回本地演示；
- 异常断线/被心跳清理 → 服务端兜底清理；客户端回本地演示（应区分提示，另见 H1）。
- **离会统一动作（v1.5 确认，共享中离会视同"正常关闭共享"）**：
  1. **共享必然关闭**：走完整关闭共享流程（触发 `onShareToggle(false)`：停共享推流与远端音频、清共享状态/标题、恢复摄像头按钮可用；保留原"自动停止共享推流"逻辑）；共享按钮随后复位为"未勾选 + 置灰禁用"（本地演示不可用态）；
  2. **摄像头按钮解除禁用**（共享期它被禁用了）；
  3. **摄像头恢复语义（v1.5 用户改选）**：若摄像头系"开启共享时被自动关闭"（`m_shareAutoPausedCam`），离会时**自动恢复开启**（与正常关闭共享一致）；若共享开启前摄像头本就关闭，则保持关闭；未共享时保持会议结束时状态（开则开、关则关）；
  4. **宫格/瓦片按启动默认配置重建一次**（本地演示 4 人、含本地模拟源），重建以**当前按钮状态**为准播种设备状态，与第 3 条结果一致。
- **保留**：任何离开/断开路径都会自动停止共享屏幕推流（`stopScreenSharing`）与远端音频。

### B.4 共享与摄像头的联动（〔修订 v1.4〕业务决策 B2 + 用户补充）
- **规则 0（v1.4：推流连接单点控制）**：`frameReady → onSelfFrameForNetwork`（网络视频推流）连接**只由本地"摄像头按钮"状态决定**（勾选=连接存在，未勾选=断开），实现上收口为单一刷新函数，在**启动后、入会后、源重建后（摄像头出错回退/设置切换设备/权限升级）、共享恢复后**按按钮状态幂等刷新（先断后连，绝不重复推帧）；**不恢复瓦片路径的第二连接点**（用户已删除以防重复推送）。摄像头默认开 → 上述时机刷新后即"入会即推流"。
- **规则 1（用户确认 v1.1 + v1.3）**：联网模式下**开启共享 → 默认直接关闭摄像头**：停止摄像头采集、本机 cam 状态置"关"，并作为真实成员状态广播 `cam=false`；服务器/远端据此如实更新该成员状态。
- **规则 1b（用户新增 v1.3）**：共享开启后，**摄像头按钮置灰禁用（不可点击）**——共享期间不允许再操作摄像头；**共享关闭后摄像头按钮恢复可用**。
- **规则 2（呈现仍须独立表达"共享中"）**：共享期间该成员的宫格内容 = 其**共享画面**（收到帧即显示），并带"共享中"角标；**不得**因 `cam=false` 显示成"摄像头已关闭"的剪影/关摄像图标；成员列表在共享期间优先呈现"共享中"。
- **规则 3（恢复语义，v1.5）**：共享关闭（会议内点关 或 共享中离会/掉线）时——摄像头按钮先恢复可用；若摄像头系"开启共享时被自动关闭"（`m_shareAutoPausedCam`），则自动恢复开启。因共享期间摄像头按钮已禁用，不再存在"共享期间用户手动关摄像"的中间态，原 03-A#10 场景随之消除。若共享开启前摄像头本就关闭，则不恢复。
- **规则 4**：本地自宫格在共享期间显示自己屏幕的预览画面（呈现议题，另行处理）。
- 现状代码与规则的差异（实施进度见《项目修改计划.md》）：①规则 0 已收口实现（syncSelfVideoNetwork）；②摄像头按钮共享期禁用已实现；③离会恢复语义按 v1.5 实现（触发完整关闭流程，非静默保持关闭）；④呈现仍当"摄像头已关闭"处理（另行议题）。

### B.5 说话高亮（〔修订〕按业务决策 B3/B6）
- "说话绿框"唯一业务来源是**真实语音检测（VAD）**：本地模式=自己麦克风 RMS；联网模式=自己本地 VAD（**远端说话状态不做跨网同步**，属有意不做）。
- **点击宫格的意图 = 切换主讲**（演讲者视图主画面），**不产生"假说话"**；
- 本地演示模式为演示需要，保留"点击=模拟该成员说话"的表现（可与"主讲"合并展示，但联网模式下必须分离）。
